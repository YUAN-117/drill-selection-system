# AI 語音輸入與登入系統 — 設計規格

## 背景與目的

現有的鑽頭選擇系統(https://yuan-117.github.io/drill-selection-system/)是純靜態網站,免費、無需登入,已上線。這份規格新增一項功能:在「鑽頭選擇」頁加入語音輸入,使用者可以直接說出「8mm 6061」這類的話,由 AI 解析成鑽頭直徑與鋁合金材質,自動填入計算表單。

因為 AI 呼叫需要付費且金鑰不能放在前端,這個功能需要後端支援,因此同時引入登入系統(僅用於這個新功能的存取控制)與後端服務(Supabase)。

## 範圍

**這次要做的:**
- Google 登入(透過 Supabase Auth),僅保護 AI 語音輸入功能
- `tool.html` 新增麥克風按鈕:瀏覽器語音辨識 → 文字 → 送到後端 → AI 解析成 `{ diameter, alloy }` → 自動填入現有的直徑/材質欄位,沿用既有計算邏輯,不重複實作
- 後端:一個 Supabase Edge Function,負責呼叫 AI(Anthropic Claude Haiku)、防濫用檢查、回傳結構化結果
- 防濫用機制:每帳號每小時 15 次請求上限、單次輸入不超過 100 字、AI 回覆長度上限(`max_tokens` 限制)
- 語音輸入紀錄:最近 20 筆存在瀏覽器 localStorage(原話、解析結果、時間),超過自動汰舊
- 解析失敗時顯示錯誤提示,要求重新說一次,不做部分猜測填入

**明確不做(YAGNI,以後有需要再擴充):**
- 付費/金流機制(這次先讓已登入使用者免費用,只用次數上限防濫用)
- 整站登入保護(現有計算器、歷史紀錄維持免登入)
- AI 對話記憶(每次語音輸入都是獨立事件,不記住上一句)
- 信箱/密碼登入方式(只做 Google 登入)
- 語音輸入紀錄的跨裝置同步(維持 localStorage,與現有歷史紀錄一致)

## 架構

```
瀏覽器(GitHub Pages 靜態網站,不變)
  │
  ├─ index.html / history.html:完全不變
  │
  └─ tool.html:新增麥克風按鈕與登入狀態顯示
       │
       ├─ 瀏覽器內建 Web Speech API:語音 → 文字(免費、前端完成)
       ├─ Supabase Auth(Google OAuth):管理登入狀態,取得存取權杖
       └─ 呼叫 Supabase Edge Function(帶著權杖與辨識出的文字)
            │
            └─ Edge Function(Supabase 後端,Deno 環境):
                 1. 驗證權杖,取得使用者 ID
                 2. 檢查該使用者本小時請求次數(查/寫一張 usage 記錄表)
                    超過 15 次 → 回傳 429 錯誤
                 3. 檢查輸入文字長度 ≤ 100 字,超過直接拒絕
                 4. 呼叫 Anthropic Claude Haiku API(金鑰存在 Supabase 環境變數,
                    絕不出現在前端),要求回傳固定格式的 JSON:
                    { diameter: number | null, alloy: string | null }
                    並設定 max_tokens 限制回覆長度
                 5. 解析失敗或欄位不完整 → 回傳「無法辨識」錯誤,不猜測填值
                 6. 成功 → 回傳結構化結果給前端
```

**Supabase 使用的功能:**
- **Auth**:Google OAuth 登入,提供使用者身分
- **Edge Functions**:一個函式(如 `parse-drill-voice`),處理上述邏輯
- **Database**:一張 `ai_usage` 表,記錄「使用者 ID + 時間窗口 + 次數」,供 Edge Function 檢查每小時上限用。不儲存語音內容本身。

**前端新增邏輯(沿用現有 core/data/ui 分層原則):**
- 語音辨識與登入狀態屬於新的 `ui` 層邏輯(碰瀏覽器 API/DOM)
- 呼叫後端、解析回應屬於新的 `data` 層(類似 `historyStore.js` 的角色,但是呼叫 Supabase 而非 localStorage)
- 語音輸入紀錄(最近 20 筆)沿用現有 `assets/data/historyStore.js` 的模式,另開一個獨立的 localStorage key,不與計算記錄混在一起

## 使用者流程

1. 使用者在 `tool.html` 點麥克風按鈕
2. 若尚未登入,顯示「請先使用 Google 登入」提示與登入按鈕,登入後才能繼續(沿用 Supabase 提供的 Google 登入流程)
3. 已登入:瀏覽器要求麥克風權限 → 開始收音 → 使用者說話 → 語音轉文字
4. 文字送到後端解析,前端顯示「辨識中」狀態
5. 成功:直徑、材質欄位自動填入,比較表如常算出結果;同時把這筆(原話+解析結果+時間)存進語音輸入紀錄(最近 20 筆)
6. 失敗(超過每小時上限 / 文字過長 / AI 無法解析):顯示對應錯誤訊息,提示使用者重新說一次,不改動任何欄位

## 錯誤處理與防濫用

| 情況 | 處理 |
|---|---|
| 未登入就按麥克風 | 顯示登入提示,不呼叫後端 |
| 該小時已用滿 15 次 | Edge Function 回傳 429,前端顯示「已達每小時使用上限,請稍後再試」 |
| 輸入文字超過 100 字 | Edge Function 直接拒絕(不呼叫 AI,省成本),前端顯示「輸入過長,請簡短描述」 |
| AI 無法解析出直徑或材質 | Edge Function 回傳解析失敗,前端顯示「聽不懂,請重新說一次,記得說出直徑與材質」,不填入任何欄位 |
| 瀏覽器不支援語音辨識 | 麥克風按鈕顯示為不可用狀態,附提示文字說明 |

## 測試策略

延續現有專案的測試方式:
- 前端純邏輯(語音辨識結果的文字前處理、語音紀錄的新增/查詢/汰舊邏輯)沿用 Node 內建 test runner 撰寫單元測試,存取方式一樣用依賴注入(參考 `historyStore.js` 的 `storage` 參數模式)
- Supabase Edge Function 的次數限制邏輯、輸入長度檢查、AI 回應格式驗證,寫成獨立的純函式並用 Deno 內建測試或 Node 測試(依實作階段決定),不依賴真的呼叫 AI API
- 與 Google 登入、真的呼叫 AI API 的整合流程,採手動瀏覽器驗證(比照現有專案模式,不寫自動化 E2E 測試)

## 需要使用者自行完成的前置作業

執行實作前,以下帳號/服務需要使用者本人親自申請(不可代辦):
1. 到 supabase.com 註冊帳號並建立新專案
2. 到 Google Cloud Console 建立 OAuth 用戶端(供 Supabase Google 登入使用)
3. 到 Anthropic(或後續選定的 AI 服務商)申請 API 金鑰,並設定好扣款方式
