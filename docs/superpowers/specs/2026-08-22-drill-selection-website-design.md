# 鑽頭選擇系統網站 — 設計規格

## 背景與目的

現有的 `drill-console.html` 是一個單頁計算器,輸入鑽頭直徑、鋁合金材質、鑽頭材質後算出建議轉速(RPM)與進給量。這份規格把它擴建成一個多頁網站服務,核心新增「鑽頭材質選擇」功能——不再要求使用者自己選鑽頭材質,而是同時算出三種材質的結果供比較。

目標使用者:任何人皆可透過網址存取,不需要註冊或登入。加工材質範圍暫定僅限鋁合金,與現有計算器一致。

## 範圍

**這次要做的:**
- 三個靜態頁面:首頁、鑽頭選擇與計算頁、歷史紀錄頁
- 鑽頭直徑輸入(自動對應市售標準規格)+ 鋁合金材質選擇 → 同時顯示 HSS / 硬質合金 / 塗層硬質合金三種材質的建議轉速與進給量對照表
- 個人歷史紀錄(存於瀏覽器 localStorage,每個使用者只看得到自己的紀錄)
- 部署到 GitHub Pages,任何人皆可透過網址存取

**明確不做(YAGNI,以後有需要再擴充):**
- 使用者帳號、登入、權限管理
- 後端伺服器、資料庫、跨使用者共用紀錄
- 鋁合金以外的加工材質
- 具體鑽頭型號/廠牌/庫存推薦(只到材質類型層級)
- 孔深、深徑比、貫穿孔/沉頭孔對進給量的影響

## 站台架構

純靜態多頁網站,不使用框架或建置工具:

```
index.html          首頁:簡介 + 導覽連結
tool.html            鑽頭選擇與計算頁(核心功能)
history.html         歷史紀錄頁
assets/style.css     共用樣式(藍色冷調視覺,沿用現有 drill-console.html 的設計語言)
assets/app.js        共用邏輯:標準鑽頭尺寸表、材質 Vc/f 對照表、計算函式、localStorage 讀寫
assets/app.test.js   單元測試(Node.js 內建 test runner,`node --test`)
```

三頁共用同一組頂部導覽列(首頁 / 鑽頭選擇 / 歷史紀錄)。計算與資料存取邏輯抽到 `app.js`,以 `<script>` 標籤在各頁引入,避免邏輯重複、也方便測試(純函式可以直接用 Node.js 匯入測試,不需要瀏覽器環境)。

## 核心邏輯:鑽頭選擇與計算(tool.html)

**輸入:**
- 鑽頭直徑(mm,數字輸入)
- 鋁合金材質(下拉選單:6061 / 7075 / A380 壓鑄鋁 / 自訂鋁合金)

**直徑正規化:**
沿用現有邏輯——直徑對應到市售標準規格(依 DIN 338 麻花鑽尺寸系列:1.0–13.0mm 每 0.1mm、13.5–20.0mm 每 0.5mm、21–32mm 每 1mm)。非標準輸入自動對應到最接近的規格,並顯示提示文字告知使用者。

**輸出:三種鑽頭材質並排比較表**

| 材質 | Vc 常用範圍 | 採用 Vc | RPM | 進給量 f | 進給速度 |
|---|---|---|---|---|---|
| 高速鋼 HSS | 30–60 m/min | 依材質係數計算 | N = 1000×Vc/(π×D) | 依直徑分段查表 | F = N×f |
| 硬質合金 | 150–300 m/min | 同上 | 同上 | 同上(與材質無關,僅依直徑) | 同上 |
| 塗層硬質合金 | 200–350 m/min | 同上 | 同上 | 同上 | 同上 |

- 各材質的採用 Vc = `min + bias×(max−min)`,bias 依鋁合金易切削程度預設(6061=0.7、7075=0.5、A380=0.35、自訂=0.5),沿用現有計算器邏輯。
- 進給量 f 只依鑽頭直徑分段查表,不因材質而異(與現有計算器行為一致,是刻意的簡化,非遺漏)。
- 附上一句簡短選用原則文字(經驗性方向,非精確判斷公式),例如:「一般用途或單件加工可選 HSS;長時間量產或需拉高轉速可選硬質合金/塗層硬質合金。」
- 所有數字皆為系統自動計算的唯讀參考值,使用者不能手動調整 Vc、f。

## 歷史紀錄

**儲存時機:** 使用者按「加入記錄」時,把當下算出的三種材質完整比較結果存成**一筆**紀錄(不需要當下決定要用哪一種)。

**資料結構(localStorage,key 由 `app.js` 統一管理,`tool.html` 與 `history.html` 共用同一份):**

```json
{
  "id": "唯一識別碼",
  "timestamp": "ISO 時間字串",
  "diameter": 8,
  "alloy": "6061",
  "alloyLabel": "6061",
  "results": [
    { "drillMat": "hss", "drillMatLabel": "高速鋼 HSS", "vc": 51, "f": 0.13, "rpm": 2029, "feedRate": 254 },
    { "drillMat": "carbide", "drillMatLabel": "硬質合金", "vc": 261, "f": 0.13, "rpm": 10390, "feedRate": 1301 },
    { "drillMat": "coated", "drillMatLabel": "塗層硬質合金", "vc": 305, "f": 0.13, "rpm": 12137, "feedRate": 1519 }
  ]
}
```

**history.html 頁面:** 每筆紀錄顯示為一個區塊(直徑+材質為標題,底下是三種鑽頭材質的小表格),可單筆刪除、可清空全部(清空前需二次確認,沿用現有 UI 模式,不用瀏覽器原生 `confirm()`)。

## 視覺設計

沿用 `drill-console.html` 已驗證過的設計系統:藍色冷調(air-conditioner 風格)、Noto Sans TC(中文內文)+ IBM Plex Mono(數字資料)、深色 LCD 風格數字讀出面板、支援亮/暗主題。三個新頁面共用 `assets/style.css`,維持視覺一致性,不重新設計。

## 測試策略

計算邏輯(標準尺寸對應、Vc/f 查表、RPM/進給量公式)寫成 `app.js` 裡的純函式,用 Node.js 內建 test runner(`node --test`,已確認環境有 Node v24 可用,不需要額外安裝套件)寫單元測試。預計涵蓋案例:

- 直徑正規化:標準尺寸原值不變、非標準值取最近規格(例如 3.672 → 3.7)、超出範圍夾在上下限(例如 40 → 32)
- 三種材質的 Vc 計算:同一直徑+材質組合,三種鑽頭材質應各自落在對應範圍內
- RPM/進給速度公式正確性:對照已知手算案例(例如 8mm、6061、HSS → Vc 51 → RPM ≈ 2029)
- 歷史紀錄的新增/刪除/清空邏輯(資料結構層級,不測 DOM)

DOM/UI 互動(表單填寫、按鈕點擊)不寫自動化測試,改用瀏覽器手動驗證(沿用這次開發計算器時的驗證方式)。

## 部署

靜態網站,無需後端。部署到 GitHub Pages,綁定現有的本機 git repo。需要使用者的 GitHub 帳號;把程式碼推上 GitHub 並開啟 Pages 屬於會公開程式碼與網站的動作,執行前會再次向使用者確認。
